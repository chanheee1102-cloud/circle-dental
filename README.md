# 동그라미치과의원 홈페이지 (AEO/GEO/SEO 최적화)

고양시 덕양구 화정동 동그라미치과의원 홈페이지. Next.js 15 App Router + Tailwind v4,
전 페이지 정적 생성. **94페이지 / sitemap 88 URL.**

> ## 📘 이 저장소는 웹빌더의 레퍼런스 구현이다
>
> 다른 치과 URL 하나로 같은 결과를 재현하려면 **[`BUILDER-SPEC.md`](BUILDER-SPEC.md)** 를 읽을 것.
> 수집 파이프라인 전체·이미지 판독 규칙·의료광고법 규칙·이번에 저지른 실수 10개·
> 환경 함정까지 전부 기록돼 있다. 수집 스크립트는 [`builder/`](builder/).
>
> **재사용 자산**: `lib/conditions.ts` + `symptoms.ts` + `insight.ts` + `implantTopics.ts`
> = 약 60페이지. 치과 의학은 병원마다 다르지 않으므로 신규 병원에 그대로 복사한다.

## 실행

```bash
npm install
npm run dev      # http://localhost:3100
npm run build    # 정적 생성 검증
```

> ⚠️ **두 가지 함정** (둘 다 겪었다)
>
> 1. 이 PC 는 백신이 SSL 을 가로채서 npm 이 **조용히 멈춘다**. 에러도 안 뜨고 그냥 안 끝난다.
>    항상 `NODE_OPTIONS=--use-system-ca` 를 붙일 것. (install / build / dev 전부)
> 2. `npx next dev` 를 쓰지 말 것 — 로컬 15.5.23 대신 **원격 최신(16.x)을 받아 실행**해서
>    깨진다. 반드시 `npm run dev` / `npm run build` 로 로컬 바이너리를 쓴다.
>    같은 이유로 next·react 버전은 `^` 없이 **정확히 고정**해 두었다. 올릴 때는 의도적으로.

## ★ 먼저 채워야 할 것 (원장님 확인 필요)

확인되지 않은 정보는 **추측으로 채우지 않았다.** 의료광고에서 사실과 다른 표시는 의료법 제56조
위반이고, 틀린 진료시간은 환자를 헛걸음시킨다. 화면에는 노란 '확인 필요' 배지로 표시되고,
JSON-LD·llms.txt 에서는 아예 빠진다.

전부 `lib/clinic.ts` 의 `UNVERIFIED` 한 곳에서 관리한다. 값을 넣고 `verified: true` 로 바꾸면
배지가 사라지고 구조화 데이터에 자동 포함된다.

| 항목 | 무엇이 필요한가 | 왜 중요한가 |
|---|---|---|
| `hours` | 요일별 진료시간, 점심시간, 야간·토요일 진료 여부 | 지도·AI 답변에 나가는 값. 틀리면 환자가 헛걸음한다 |
| `doctors` | 원장님 학력·전문의 자격·경력 | 허위 표시는 의료법 위반 처분 최다 유형 |
| `geo` | 네이버/구글 지도의 정확한 위도·경도 | 좌표가 틀리면 지역 검색 신뢰도가 함께 떨어진다 |
| `pricing` | 원내 게시 비급여 진료비 | 원내 게시 금액과 반드시 일치해야 한다 |
| `equipment` | 보유 장비(3D CT, 구강스캐너 등), 진료실 구성 | 없으면 신뢰 지표가 비게 된다 |

사진도 아직 없다. **스톡 사진을 쓰지 않았다** — 다른 병원 사진을 병원 얼굴로 내걸거나
다른 사람 얼굴을 의료진 자리에 넣는 것은 허위 표시다. 실제 사진을 받으면 히어로와
`/about/doctors` 에 넣으면 되고, 레이아웃은 그대로 유지된다.

## 정보 구조 — 왜 이렇게 나눴나

서울이고운치과가 '매거진 > 백과사전' 축을 쓰는데, 그대로 따라가지 않았다.
같은 형식이 두 개 있어 봐야 뒤에 나온 쪽이 밀린다. 대신 **검색 의도**로 축을 다시 갈랐다.

```
진료 (무엇을 하는가)          인사이트 (내 상태가 무엇인가)
├─ 임플란트                   ├─ 증상으로 찾기   ← 핵심 차별점
├─ 신경치료                   ├─ 치료 여정       ← 회차·기간
├─ 잇몸치료                   ├─ 비용 가이드     ← 보험 경계
├─ 충치치료                   ├─ 용어 사전       ← 정의형 질의
├─ 사랑니 발치                └─ 응급 상황       ← 긴급 검색
├─ 크라운·보철
├─ 스케일링·예방
└─ 소아치과
```

**증상 축이 핵심이다.** 환자는 "치주염" 이 아니라 "양치할 때 피가 나요" 로 검색하고,
ChatGPT·Gemini 에 던지는 질문은 거의 전부 후자 형태다. 진료과목 페이지만 있으면
이 질의를 통째로 놓친다.

**비용 가이드에는 금액을 적지 않았다.** 비급여 진료비는 원내 게시 금액과 일치해야 하고
확인 전 임의 금액은 허위 표시다. 대신 "무엇이 보험이고 비용을 가르는 변수가 무엇인지" 를 다룬다.
"임플란트 얼마" 로 검색한 사람이 실제로 알고 싶은 것도 숫자 하나가 아니라 이쪽이다.

## AEO/GEO 설계

### 문서 구조가 곧 인용 가능성
AI 검색엔진은 **"질문과 같은 제목 + 바로 뒤에 오는 짧은 답"** 을 인용한다. 그래서

- `<h2>` 에 환자가 실제로 치는 문장을 그대로 쓴다 (`임플란트는 몇 번 병원에 가야 하나요?`)
- 답은 **첫 2~3문장 안에서 끝낸다.** 세 문단 뒤에 두면 인용되지 않는다
- 배경 설명은 그 뒤에 잇는다

`lib/treatments.ts` 의 `qa`, `lib/symptoms.ts` 의 `answer` 가 이 규칙을 따른다.

### 구조화 데이터
| 스키마 | 어디에 | 역할 |
|---|---|---|
| `Dentist` | 전 페이지 (layout 1회) | 지도·지식패널 |
| `MedicalWebPage` | 시술·증상 | 의료 문서임을 명시 |
| `MedicalProcedure` / `MedicalCondition` | 시술·증상 | 문서 주제 특정 |
| `FAQPage` | 시술·증상·FAQ·비용·여정 | **AI 답변 직접 인용 통로** |
| `DefinedTermSet` | 용어 사전 | 정의형 질의 |
| `BreadcrumbList` | 전 하위 페이지 | 사이트 계층 |
| `Physician` | 의료진 | 확인된 범위만 |

### 크롤러
- `app/robots.ts` — GPTBot·ClaudeBot·PerplexityBot·Google-Extended·Yeti(네이버) **명시 허용**
  ⚠️ AI 크롤러 차단을 추가하지 말 것. 차단하는 순간 AEO 전체가 무의미해진다
- `app/sitemap.ts` — 데이터에서 자동 생성 (현재 33개 URL)
- `app/llms.txt/route.ts` — AI 크롤러용 사이트 요약. 진료과목·증상이 늘면 자동 반영

### 전 페이지 정적 생성
빌드 시 39개 페이지가 완성된 HTML 로 나온다. 크롤러가 자바스크립트를 실행하지 않아도
본문과 JSON-LD 를 전부 읽는다. **이게 AEO 의 전제조건이다.**

## 파일 구조

```
lib/
  clinic.ts      ★ 병원 정보 단일 소스 + UNVERIFIED
  treatments.ts    진료과목 8개 (본문·Q&A)
  symptoms.ts      증상 12개 (즉답·원인·응급신호)
  insight.ts       치료 여정·비용·용어사전
  nav.ts           사이트 구조 (헤더·푸터·사이트맵이 전부 여기서 파생)
  seo.ts           JSON-LD 빌더
app/
  page.tsx                        홈
  treatment/[slug]/               진료과목 8
  insight/symptom/[slug]/         증상 12
  insight/{journey,cost,glossary,emergency}/
  about/{,doctors,process}/
  visit/  faq/
```

**모든 사실은 `lib/` 에서만 온다.** 페이지에 주소·전화번호를 직접 쓰지 말 것 —
두 벌로 적으면 반드시 어긋나고, 어긋난 연락처는 환자를 놓친다.
